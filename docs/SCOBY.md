# SCOBY Integration

## Overview

SCOBY (System COmponent BYstem) provides system health monitoring capabilities to Briefly. It scans log directories and system locations to identify errors, warnings, and anomalies that may indicate system issues.

## Components

### 1. ScobyProvider (`Sources/Core/Providers/ScobyProvider.swift`)

A Swift provider that implements the `Provider` protocol and provides:

- **Log File Analysis**: Scans configured log directories for error patterns
- **Warning Detection**: Identifies warning-level log files
- **Crash Report Monitoring**: Checks standard crash report locations
- **Log File Growth Tracking**: Identifies unusually large log files
- **Markdown Report Generation**: Creates structured health reports

**Key Features:**
- Scans multiple log directories: `./logs`, `~/Library/Logs`, `/var/log`
- Pattern matching for error files: `*error*.log`, `*fatal*.log`, `*exception*.log`, `*crash*.log`
- Pattern matching for warning files: `*warning*.log`, `*warn*.log`
- Automatic deduplication of findings
- Human-readable file size formatting

### 2. ScobyExportCommand (`Sources/CLI/Commands/ScobyExportCommand.swift`)

A CLI command that provides export functionality with the following options:

- `--date, -d`: Specify a date for analysis (YYYY-MM-DD format, defaults to today)
- `--output, -o`: Custom output path (defaults to `./logs/scoby-report-YYYY-MM-DD.md`)
- `--verbose, -v`: Show detailed progress information
- `--quiet`: Suppress all output except errors
- `--critical-only`: Include only errors and critical warnings
- `--max-size`: Maximum log file size to analyze in MB (default: 50, use 0 for unlimited)

## Usage

### Basic Usage

```bash
# Generate a report with default settings
briefly scoby-export

# Generate a report for a specific date
briefly scoby-export --date 2025-01-15

# Save to a custom location
briefly scoby-export --output ~/Documents/scoby-report.md

# Show only critical issues
briefly scoby-export --critical-only

# Verbose output
briefly scoby-export --verbose

# Quiet mode (for scripting)
briefly scoby-export --quiet --output /tmp/report.md
```

## Architecture

The SCOBY integration follows Briefly's standard patterns:

- **Provider Pattern**: Implements `Provider` protocol for consistency
- **Async/Await**: All operations are asynchronous
- **Swift 6**: Uses modern Swift concurrency features
- **No External Dependencies**: Pure Swift implementation using Foundation

## Future Enhancements

Potential improvements for future iterations:

1. **Date-Aware Scanning**: Filter log entries by actual timestamps, not just file modification dates
2. **Custom Log Directories**: Allow users to specify additional log directories via configuration
3. **Trend Analysis**: Track health metrics over time
4. **Alert Thresholds**: Configure alert thresholds for error counts
5. **MCP Integration**: Expose SCOBY as an MCP tool for automated monitoring
6. **JSON Output**: Add JSON format option for programmatic consumption
7. **Log Parsers**: Add specialized parsers for known log formats (e.g., system.log, app logs)

## Integration with Briefly

To integrate SCOBY reports into Briefly's daily briefings, you could:

1. Add a method to `BriefService` that calls `ScobyProvider.fetchHealthObservations()`
2. Include SCOBY observations in the `DailyBrief` model
3. Display SCOBY data in the `brief` command output

Example integration (pseudo-code):

```swift
// In BriefService
let scobyProvider = ScobyProvider()
let healthObservations = try await scobyProvider.fetchHealthObservations(for: date)

// Include in DailyBrief
let brief = DailyBrief(
    // ... other fields ...
    systemHealth: healthObservations.isEmpty ? nil : healthObservations
)
```
