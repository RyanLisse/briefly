Your daily briefing companion that synthesizes information from communication channels, calendar, and health data into concise summaries with optional voice output.

## What you get

| Feature | Description |
|---------|-------------|
| **Daily Brief** | Comprehensive summary from all data sources |
| **Voice Output** | Local MLX models (Kokoro-82M, LFM 2.5) for fast, private audio briefings |
| **Multiple Sources** | iMessage, WhatsApp, Gmail, Calendar, Notes, Whoop, GitHub, LinkedIn |
| **MCP Server** | All features exposed as MCP tools for AI agents |

## Quick Install

```bash
# Clone the repository
git clone https://github.com/RyanLisse/briefly.git
cd briefly

# Run setup (installs dependencies, downloads local models, configures environment)
make setup

# Build and install
make install

# Generate your first brief
briefly brief
```

The setup script will:
- ✅ Install Swift dependencies
- ✅ Set up Python environment for MLX models
- ✅ Download local voice models (Kokoro-82M, LFM 2.5 Audio)
- ✅ Configure environment with local models as default
- ✅ Set up HuggingFace authentication

## Quick Start

```bash
# Today's brief
briefly brief

# Specific date
briefly brief --date 2026-01-09

# With voice output (uses local MLX models by default)
briefly brief --voice

# JSON output
briefly brief --json

# Limit items per source
briefly brief --limit 25

# Include yesterday's data for comparison
briefly brief --yesterday
```

### Using Makefile Commands

For convenience, you can also use Makefile shortcuts:

```bash
make brief          # Generate today's brief
make brief-voice    # Generate brief with voice
make brief-json     # Generate brief in JSON format

```

| Command | Key flags | What it does |
|---------|-----------|--------------|
| `brief` | `--date`, `--voice`, `--json`, `--limit` | Generate daily briefing |
| `pulse` | `--json` | Quick status check |

| `mcp serve` | - | Start MCP server |

## Architecture

Follows the [Peekaboo](https://github.com/steipete/Peekaboo) architecture standard:

```
Sources/
├── Core/           # BrieflyCore - framework-agnostic library
│   ├── Models/     # Message, BriefOutput
│   ├── Providers/  # DataProvider protocol + 8 implementations
│   └── Services/   # BriefService, SynthesisService, etc.
├── CLI/            # BrieflyCLI - ArgumentParser commands
│   └── Commands/   # Brief, Pulse, Setup, MCP
├── MCP/            # BrieflyMCP - MCP server with handler pattern
│   └── Handlers/   # ToolHandler
└── Executable/     # Main entry point
```

## Configuration

Configuration is managed via the `.env` file, which is created automatically during setup.

### Voice Engine Configuration

**Default: Local MLX Models** (recommended)
- Uses Kokoro-82M for normal voice synthesis
- Uses LFM 2.5 Audio for premium/high-quality synthesis
- Fast, private, no API costs
- Models are downloaded automatically during setup

**Fallback: Cloud (ElevenLabs)**
- Set `VOICE_ENGINE=cloud` in `.env`
- Requires `ELEVENLABS_API_KEY` in `.env`

```bash
# In .env (auto-generated by setup)
VOICE_ENGINE=local          # Default: use local MLX models
VOICE_PROFILE=normal        # normal (Kokoro) or premium (LFM 2.5)
STT_PROFILE=parakeet        # Speech-to-text profile

# Optional: Fallback to ElevenLabs
# VOICE_ENGINE=cloud
# ELEVENLABS_API_KEY=your-api-key
```

### Other API Keys

Add these to `.env` as needed:

```bash
# Gmail (optional)
GMAIL_CLIENT_ID=your-client-id
GMAIL_CLIENT_SECRET=your-client-secret

# Google/Gemini API
GOOGLE_API_KEY=your-api-key
GEMINI_API_KEY=your-api-key

# Whoop Health
WHOOP_CLIENT_ID=your-client-id
WHOOP_CLIENT_SECRET=your-client-secret
WHOOP_REDIRECT_URI=http://localhost:8000/auth/callback
```
